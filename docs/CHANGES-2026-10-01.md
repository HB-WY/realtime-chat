# 修复与变更说明（2026-10-01）

本轮修复源自全量代码审核（安全 / 业务逻辑 / 前端 / 仓库卫生），并按需求调整了上架权限与上传限制。

## 一、按需求调整

### 1. 普通用户可上架（list_products 语义修正）
- `list_products`（50 级）原本拦住**全部**上架通道（上传 / 封面 / 建品），普通用户连跳蚤市场都无法上架。
- 现在只有**官方市场**（`market='official'`）受 `official_publish`（50 级）拦截；跳蚤市场 / 标准市场对所有登录用户开放。
- 前端：「+ 上架商品」按钮对所有用户显示；上架弹窗中「官方市场」选项按 `official_publish` 能力禁用（服务端同步拦截，双保险）。

### 2. 上传限制：单次 ≤500MB，不再有 200MB 总量
| 项 | 原值 | 新值 |
| --- | --- | --- |
| 聊天附件单文件（`uploads.limits.file`） | 100MB | **500MB** |
| 商品文件单文件（`shop_file`） | 200MB | **500MB** |
| 资源池单文件（`asset`） | 10MB | **500MB** |
| 资源池单次批量（`batch_max_bytes`） | 200MB | **500MB** |
| 资源池用户总量（`quota_bytes`） | 200MB | **0 = 不限** |

- `assets.js`：`quota_bytes ≤ 0` 视为不限总量（单次 / 单文件上限与频率限流仍然生效）。
- 前端「我的资源」配额条适配：不限总量时显示「已用 X MB（总量不限）」。
- 作为取消总量配额的补偿，新增**按用户上传频率限流**（`rate_limits.upload`，默认 20 次/分钟），覆盖聊天附件 / 头像 / 商品文件 / 封面 / 资源池全部通道。

## 四、中优先级修复

- **消息清洗**：`file_name` 服务端剥控制字符与 `<>`（chat.js `sanitizeFileName`）
- **socket 限流改按用户**：`makeRateLimiter` 进程级 Map，多开连接不再放大额度；`users:search`/`groups:search`/`user:refresh`/`message:read` 补限流；`room:open` 鉴权失败回 ack 错误
- **REST 发消息限流**：`POST /api/v1/messages` 按用户限流（与 socket 同参数）
- **转码**：`max_source_bytes` 0→500MB（防 CPU DoS）；失败记录加 30 分钟 TTL（不再永久失败）；`/api/media/status` 按用户限流
- **API 密钥**：移除 `?api_key=` URL 通道（防日志/Referer 泄露）；遗留 NULL `bound_ip` 不再「首次使用就绑定」而是拒绝
- **路径前缀校验**：download.js 两处 `startsWith` 补 `path.sep`（与 `isInsideDir` 口径一致）；preview async handler 补 try/catch（Express 4 不捕获 rejection）
- **每日额度口径**：转账排除 `expired`、红包排除 `expired`（退款后额度不再虚耗）；transfers 删掉吞错的 `assertRoomAccess` try/catch
- **官方账户**：不再被 `ensureAccount` 发放注册积分（0 余额开户，seed 显式建户）；seed 补积分包进事务
- **数据库索引**：补 `friendships(friend_id)`、`friend_requests(from_id,status)`、`group_requests(user_id,status)`、`groups(owner_id)`、`orders(product_id,buyer_id)`、`messages(sender_id)`
- **撤回事务化**：两条 DELETE 包进 transaction（不再留孤儿回执）
- **商品搜索**：`instr` 改大小写不敏感
- **插件落盘原子化**：先写临时目录，DB 成功后再 rename（失败自动清理）
- **表情包商品跳转**：`sticker_packs.product_id` 直查（原 `UPDATE...LIMIT` 死代码 + assets 反查从未生效）；`grantedPackId` 不再按名称模糊反查
- **全局响应头**：API 统一 `nosniff` / `X-Frame-Options: SAMEORIGIN` / `Referrer-Policy: same-origin`
- **前端 socket 过期**：认证类 `connect_error` 派发 `auth:expired` 回登录页，并停止无限重连
- **依赖**：移除从未使用的 `cors`

## 六、已知取舍（未改动，有意保留）

- `/uploads/*` 静态目录仍不鉴权（`<img>` 无法带 Authorization 头），安全性依赖 CSPRNG 文件名不可猜测；彻底方案是 HMAC 签名 URL，属后续迭代
- 限流计数器仍是进程内 Map（单机部署前提，重启清零）
- JWT 仍存 localStorage（无 XSS 向量前提下的既有取舍）
- `points.frozen` 死字段保留（删列成本大于收益）
- 转码副本 `uploads/*/tc/` 无自动清理（可跑 `cleanup_orphan_files.mjs`）
